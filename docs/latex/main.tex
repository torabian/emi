\lettrine[lines=3,lraise=0.1,nindent=0pt]{E}{mi} is a code generator: you
describe an API once --- DTOs, entities, actions, config, permissions,
events --- in a single YAML (or JSON) definition, and Emi compiles that one
definition into working, type-safe code for Go, TypeScript/JavaScript,
Swift, Kotlin, and more, plus an OpenAPI document and a Postman collection.
This issue of the Gazette walks the compiler floor, feature by feature, so
a new contributor can find their desk quickly.

Every team that ships an API ends up writing the same contract twice: once
on the backend, again by hand on every client. Emi exists to make that
contract a real, compilable thing, and generate every side of it so the
drift problem stops existing rather than getting managed.

\begin{sidebar}{Quick start}
\begin{lstlisting}
go install \
  github.com/torabian/emi/cmd/emi@latest
emi go    --path module.emi \
  --output ./server
emi js    --path module.emi \
  --output ./web/sdk --tags react
emi swift --path module.emi \
  --output ./ios
\end{lstlisting}
\end{sidebar}

\begin{pullquote}
``OpenAPI describes an API that already exists. gRPC replaces your
transport with its own. Emi generates the API itself --- backend and
every client --- as ordinary, runtime-free, idiomatic code you fully
own.''
\end{pullquote}

\begin{sidebar}{Compilers at a glance}
\begin{itemize}[leftmargin=1.1em,itemsep=1pt,topsep=2pt]
  \item \texttt{emi go} --- Gin server, client \& CLI
  \item \texttt{emi js} --- JS/TS classes, React, Nest.js
  \item \texttt{emi swift} / \texttt{emi kotlin} --- native clients
  \item \texttt{emi openapi} / \texttt{postman} / \texttt{md} --- docs
  \item \texttt{emi qp:dir} / \texttt{qp:gen} --- typed SQL bindings
  \item same compiler, compiled to \textbf{WASM} --- runs in-browser
\end{itemize}
\end{sidebar}
